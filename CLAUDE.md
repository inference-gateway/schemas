This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The `inference-gateway/schemas` repo holds the three shared schemas the rest of the ecosystem (gateway, SDKs, docs, CLI, operator) consumes:

- `openapi.yaml` — Inference Gateway's HTTP API spec. **Hand-edited; source of truth.**
- `a2a/` — A2A (Agent-to-Agent) protocol. `a2a.proto` is the source of truth; `a2a-schema.json` / `.yaml` are **generated** from it.
- `mcp/` — Model Context Protocol schema. **Mirrored** from `modelcontextprotocol/modelcontextprotocol`; both the JSON and YAML are generated.

Downstream consumers regenerate from these files, so a schema change here ripples into `inference-gateway/sdks`, `inference-gateway/docs`, and others. See the `maintainer` skill / cross-repo checklist before shipping a breaking change.

## Commands

All tasks go through `Taskfile.yml`. `task --list` enumerates them; the load-bearing ones are:

| Task | What it does |
| --- | --- |
| `task openapi:lint` | Spectral lint of `openapi.yaml` (CI runs this on every push/PR). |
| `task openapi:format` | `prettier --write openapi.yaml` (single quotes, 2-space). |
| `task mcp-schema-download` | Fetches the MCP JSON schema for the pinned protocol version (`MCP_PROTOCOL_VERSION` in `Taskfile.yml`, currently `2026-07-28`) from upstream, regenerates the YAML. Bump the pin when a new revision ships. |
| `task a2a-schema-download` | Runs `buf generate` on `a2a/a2a.proto` → bundled JSON schema → post-processed `a2a-schema.{json,yaml}`. Requires Go + `buf` on PATH. |
| `task release:dry` | Previews the next semantic-release version + notes locally (`bun install` then `bun run release:dry`, i.e. `semantic-release --dry-run --no-ci`); publishes nothing. Needs `GITHUB_TOKEN`/`GH_TOKEN` exported and push access to `main` - the dry run still does `git push --dry-run` and the `@semantic-release/github` verifyConditions check, which fails with `ENOGHTOKEN` without a token. |

`bun scripts/check-reachable.js [path]` — sanity-checks that streaming-payload schemas (`CreateChatCompletionStreamResponse` and friends) are still reachable from operations in `openapi.yaml`. `oapi-codegen` drops unreachable schemas during code generation; this prevents regressions of issue #31.

The two schema-sync tasks are also exposed as `workflow_dispatch` GitHub Actions (`a2a-schema-sync.yml`, `mcp-schema-sync.yml`) that open a `chore(scope): sync …` PR automatically.

Releases are automated with **semantic-release** (config in `.releaserc.yaml`), triggered manually via the `workflow_dispatch` `Release` workflow (`release.yml`). It derives the version from Conventional Commits, updates `CHANGELOG.md`, tags, and creates a GitHub Release. Nothing is published to a package registry. `feat:` → minor and a `BREAKING CHANGE:` footer → major; `fix:`, `chore:`, `ci:`, `refactor:`, `perf:` and reverts all cut a patch (`releaseRules` in `.releaserc.yaml` plus the commit-analyzer defaults). Only `docs:`, `style:`, `test:` and `build:` do not release.

## Generated files — do not hand-edit

- `a2a/a2a-schema.json`, `a2a/a2a-schema.yaml` — regenerated by `task a2a-schema-download`. To change A2A types, edit `a2a/a2a.proto`, then rerun the task. Despite its name the task never downloads the proto — it compiles the committed `a2a/a2a.proto` (only `buf.yaml` and the codegen plugin come from the network), so picking up upstream (`a2aproject/A2A`, `specification/a2a.proto`) changes means copying them into that file by hand first, or changing the task to fetch it.
- `mcp/mcp-schema.json`, `mcp/mcp-schema.yaml` — mirrored from upstream. Don't patch locally; fix upstream or rerun `task mcp-schema-download`.

`openapi.yaml` **is** the source — edit it directly.

## A2A generation pipeline (why the scripts exist)

`task a2a-schema-download` is a three-stage pipeline over the committed `a2a/a2a.proto`; the `scripts/` stages do what `buf`/`protoc-gen-jsonschema` alone can't. (`scripts/` also holds `sort-keys.js`, a helper both pipeline scripts use for deterministic key ordering, and `check-reachable.js`, which belongs to `openapi.yaml` and has nothing to do with A2A.)

1. **`buf generate`** — emits per-message `*.jsonschema.strict.bundle.json` files into `a2a/` using the `target=json-strict-bundle` plugin option.
2. **`scripts/process-bundle.js`** — merges all bundle files into a single `a2a-schema.{json,yaml}` under `definitions:`, then:
   - strips MkDocs `--8<-- [start:X]` / `[end:X]` snippet markers from descriptions (proto comments include them so docs can include slices verbatim);
   - strips namespace prefixes (`a2a.v1.`, `google.protobuf.`) from definition keys **and** `$ref` strings — note it only knows those two, so a package rename upstream (`main` is now `lf.a2a.v1`) needs this script updated too;
   - rewrites `#/$defs/` → `#/definitions/`;
   - deletes `patternProperties` (downstream codegen doesn't handle them);
   - removes the per-message bundle files.
3. **`scripts/add-required-fields.js`** — loads `scripts/parse-proto-required.js` (a module, not a separate task step), which parses `a2a.proto` for `[(google.api.field_behavior) = REQUIRED]` annotations and returns `{ MessageName: [camelCaseField, …] }`, then writes those arrays back into the merged schema (both `.json` and `.yaml`).

   The plugin *does* emit `required` — one entry per implicit-presence scalar or enum field — so this stage **overwrites** rather than adds: the 26 annotated messages get the proto's REQUIRED list, and the other 13 definitions keep the plugin's presence-derived array. That mismatch is a bug, tracked in #249.

If you touch any of these scripts, run `task a2a-schema-download` end-to-end and diff the output against `main` — they're load-bearing for SDK codegen.

## Conventions

- **Commits:** Conventional Commits, all-lowercase description (`chore(mcp): sync MCP schema`, `feat(openapi): add foo endpoint`). Semantic-release downstream depends on this.
- **YAML/Markdown style:** 2-space indent, single quotes, LF endings, final newline (`.editorconfig` + `.prettierrc`).
- **CODEOWNERS:** `a2a/*` is owned by `@inference-gateway/a2a` — expect that team on any A2A-touching PR.
- **CI:** runs `bun run lint` (markdownlint) and `bun run openapi:lint` (Spectral) on every push/PR. There's no test suite; the sync workflows themselves are the regression net for the generated schemas.
